# サクラエディタの正規表現（bregonig.dll）

## 対象と公式の資料

- 調べた処理系: サクラエディタ 2.4.2（Win32 版）に付いている `bregonig.dll` 4.20（中で使う正規表現ライブラリは Onigmo 6.2.0）
- 公式の資料
  - [サクラエディタのヘルプ: 正規表現ライブラリ（HLP000006）](https://sakura-editor.github.io/help/HLP000006.html)
  - [サクラエディタのヘルプ: 利用可能な正規表現（HLP000089）](https://sakura-editor.github.io/help/HLP000089.html)
  - [Onigmo の正規表現の資料（doc/RE）](https://github.com/k-takata/Onigmo/blob/master/doc/RE)
- `bregonig.dll` の作者のページ（k-takata.o.oo7.jp）は、読みに行ったときに見つかりませんでした（404）

## サクラエディタでの使われ方

ヘルプによると、サクラエディタは検索の文字列を `m(区切り)パターン(区切り)km` の形で `bregonig.dll` に渡します。大文字と小文字を区別しないとき（検索ダイアログの「英大文字と小文字を区別する」のチェックを外したとき）は、最後に `i` を付けます。これにより、次のようになります。

- **m（複数行）が最初から付いている。** `^` と `$` は指定しなくても各行の先頭と末尾に一致します（実際の結果）
- **`.` は CR と LF のどちらにも一致しない。** Unicode 版では、サクラエディタ本体が `.` を `[^\r\n]` に置き換えてから渡します（ヘルプ）。`bregonig.dll` だけに渡すと、`.` は CR に一致します
- CRLF の改行を探すときは `\r\n` と書きます（ヘルプ）
- 検索・置換・Grep では、`/` をエスケープする必要はありません（ヘルプ）

本体のソース（v2.4.2 の `CBregexp::MakePatternAlternate` と `CSearchAgent::SearchWord`）では、さらに次のことをしていました。

- **`$` も置き換える。** `\` の付いていない、文字クラスと `\Q…\E` の外の `$` を `(?<![\r\n])(?=\r|$)` にします。そのため、`$` は CR と LF のどちらの直前にも一致します。文字クラスは `[` と `]` の数で入れ子の深さを数えるので、`[[:alnum:]_.-]` の中の `.` は置き換えません。ただし `[].]` は、最初の `]` で文字クラスが終わったとみなして、あとの `.` を置き換えます。後読みの中の `$`（`(?<=a$)` など）は、置き換えると後読みの中に先読みが入るので、誤り（invalid pattern in look-behind）になります（実際の結果）
- **1 行ずつ探す。** 行末の改行（CRLF、LF、CR）を含めた 1 行を、1 つの文字列として `bregonig.dll` に渡します。そのため、改行のあとの文字まで続けて一致することはなく、先読み・後読みも前後の行を見ません。`\A`、`\z`、`\Z` は各行の先頭と末尾に一致します。探し始める位置は行末の改行の前までです

このツールのサクラエディタのモードは、これらも含めて、サクラエディタ本体での動きに合わせています（`dialects.js` の `sakuraEditorPattern` と `match-core.js` の `findAllPerLine`）。照らし合わせの道具（`tools/dialect-probe/probe-sakura.ps1`）も、同じ置き換えをしてから 1 行ずつ `bregonig.dll` で探します。

## 正規表現の中のオプション

`(?imsx-imsx)` と `(?imsx-imsx:…)` が使えます。i は大文字と小文字を区別しない、s は `.` を改行にも一致させる、x は空白を無視する、です。m はサクラエディタでは最初から有効です（ヘルプ）。ただし、本体が `.` を `[^\r\n]` に置き換えるので、s を付けても `.` は改行に一致しません。

`(?i)` は、書いた位置からグループの終わりまでを 1 つのまとまりにします。そのため、`a(?i)b|c` は `a(?i:b|c)` と同じになり、`c` だけの文字列には一致しません（実際の結果）。ほかの言語では、`a(?i)b|c` は `c` にも `C` にも一致します。`(?^i)` は、フラグをすべて外してから i を付けます。フラグのない `(?)` は誤りです（実際の結果）。

## 大文字と小文字を区別しないとき

- `\w` や `[[:lower:]]`、`\p{Lu}` などの文字の集まりにも効きます。`(?i:\w)` はケルビン記号（U+212A）と ſ にも一致します。ただし `[[:^lower:]]` は、小文字以外の文字（A など）のほか、それと同じとみなす小文字（a）にも一致します（実際の結果）
- **`ß` と `ss`、`ﬀ` と `ff`、`ŉ` と `ʼn` のように、1 文字と、その文字を広げた 2〜3 文字の並びを同じとみなします。** `(?i)ß` は `ss` と `SS` に、`(?i)ss` は `ß` に、`(?i)[ß]` は `ss` に一致します。`(?i)sss` は `ßs` にも `sß` にも一致します（どれも実際の結果）。ほかの言語は、1 文字どうしでしか比べません
- 後読みの中では、広げた並びだけに一致します。`(?i)(?<=ß)x` は `ssx` の x に一致しますが、`ßx` の x には一致しません（実際の結果）

## 文字の集まり

- `\d` は Unicode の 10 進数字（全角数字も含む）です（ヘルプ「Unicode 版では全角数字も含む」と実際の結果）
- `\w` はひらがな、カタカナ、漢字にも一致します。Onigmo の資料では「Letter、Mark、Number、Connector_Punctuation」とありますが、実際には ① のような数字（No）の多くには一致せず、² ³ ¹ ¼ ½ ¾ には一致しました
- `\s` は全角スペースと U+0085 にも一致します（実際の結果）
- `\v` も垂直タブではなく「v」という文字として読みました（実際の結果）
- `\h` は、「h」という文字そのものとして読みました（実際の結果）。Onigmo の資料では `\h` は16進数の数字とされていますが、サクラエディタではそうなりませんでした。Java や PHP の「横方向の空白」の意味でもありません
- `\R` は改行の並びです。CRLF に一致したあと、CR だけに戻って試し直さないので、`\R\n` は CRLF に一致しません（実際の結果）
- POSIX の書き方 `[[:alpha:]]` と、文字クラスの `&&`（共通部分）と入れ子が使えます。`[:alpha:]` は Unicode の Alphabetic の性質（Ⅰ のようなローマ数字も含む）、`[:upper:]` と `[:lower:]` は Uppercase と Lowercase の性質、`[:punct:]` は `\p{P}` と ASCII の記号（`$` や `+` など）に一致しました。`[:graph:]` は空白・制御文字・未割り当て・サロゲート以外、`[:print:]` はそれに空白（Zs）を足した範囲でした（実際の結果）

## 位置

- `^` と `$` は各行の先頭と末尾です（m が最初から付いているため）。`$` は、CR と LF のどちらの直前にも一致します（本体の置き換え）
- 1 行ずつ探すので、`\A` は行の先頭、`\z` は行の終わり（行末に改行があれば、その改行のあと）、`\Z` は行の終わりか行末の改行の直前です。`\G` は探し始めた位置です
- `\b` と `\B` が使えます。`\w` が日本語にも一致するので、日本語の文字と記号の境目も単語の区切りになります
- `^*` のように、位置を表す部品を繰り返しても誤りになりません（実際の結果）

## グループと参照

- 名前付きグループは `(?<name>…)`、`(?'name'…)`、`(?P<name>…)` のどれも使えました（実際の結果。ヘルプと Onigmo の資料には `(?P<name>…)` は載っていません）
- 参照は `\1`、`\k<name>`、`\k'name'`、`\k<1>`（番号）、`(?P=name)`、`\g{1}`、`\g{-1}`（相対）、`\g{name}` が使えました。グループ名には漢字なども使えます。名前付きと名前なしのグループを混ぜても、番号は左から順に付きました（実際の結果）
- グループの中から、そのグループ自身を参照すると、参照は必ず失敗します。`(a|b\1)+` は `aba` の全体には一致せず、`a` だけに一致します。Java、PHP、C# では、前の回に一致した文字列と比べるので、`aba` に一致します（実際の結果）
- 同じ名前のグループを置けます
- 一致しなかったグループへの参照は失敗します
- アトミックグループ `(?>…)` と強欲な繰り返し（`*+` など）が使えます
- 後読みの中身は、`|` の候補ごとに長さが決まっている必要があります（Onigmo の資料: 候補ごとなら長さが違ってよい）。`(?<=a+)` や `(?<=a{1,3})` は誤りです。中身全体を `(?:…)` で囲んだ `(?<=(?:a|bc))` も、その中の候補ごとに見るので書けます（実際の結果）
- 後読みの中には後方参照、先読み、アトミックグループ、強欲な繰り返しを書けません。否定の後読み `(?<!…)` の中にはグループ `( )` も書けません（どれも実際の結果）
- `(?#…)` はコメントです
- `a**` のように繰り返しを重ねても誤りになりません。`?`、`*`、`+` とその「最短で一致」の形を重ねると、Onigmo の表に従って 1 つの繰り返しにまとめます。たとえば `x+?+` と `(?:x+?)+` は `x+?` と同じになり、`xxx` に 1 文字ずつ 3 回一致します。ほかの言語では `(?:x+?)+` は `xxx` 全体に一致します（実際の結果。36 通りの重ね方を、それぞれ 9 つの形で調べました。まとめ方は Onigmo のソースの onig_reduce_nested_quantifier の表として知られていますが、ソースそのものは確かめていません）
- `{n,m}` の数は 100000 までです（実際の結果）
- `\X`（見た目の 1 文字にまとまる文字の並び）と `\K` も使えますが、このツールは対応していません

## エスケープ

- `\x{41}` のように、`{}` で囲んだ16進数で文字を書きます
- **`\x41` や8進数の `\012`、`\0` は誤りになります。** Unicode 版の `bregonig.dll` では「too short multibyte code string」という誤りになりました（実際の結果）。Onigmo の資料では `\xHH` は「バイトの値」とされていて、1 文字が 2 バイトの UTF-16 では 1 バイトだけでは文字にならないためと考えられます（推測）
- `\u0041` はエスケープではなく「u0041」という文字の並びとして読みました（実際の結果）
- `\t \n \r \f \a \e`、`\cX`、`\o{…}`、`\Q…\E` が使えます。`\cX` は、X の文字コードの下位 5 ビットと最上位のビットを残した値（0x9F とのビットごとの論理積）の文字です（`\c1` は U+0011、`\c?` は DEL。実際の結果）
- `\x{}` や `\x{ 41 }` のように `{}` の中が16進数でないときは、`x{}` のような文字の並びとして読みます。`\x{110000}` のように大きすぎる値は、誤りにならず、どの文字にも一致しません（実際の結果）
- 意味のない英字のエスケープ（`\q` など）は、その文字として読みました（実際の結果）
- `\p{Alphabetic}` のような二値の性質と、`\p{^L}`（`\P{L}` と同じ）が使えます。性質の名前は大文字と小文字、空白、`-`、`_` を区別しません（実際の結果）。`{}` を省いた `\pN` は誤りにはなりませんが、数字には一致しませんでした（実際の結果）
- 性質の名前には、ほかに次のものが使えました（実際の結果）
  - 一般カテゴリの長い名前と別名（`\p{Letter}`、`\p{Punct}`、`\p{Digit}`）
  - 二値の性質の略称（`\p{Alpha}`、`\p{Lower}`、`\p{Space}`、`\p{Hex}`）と、`\p{Any}`、`\p{ASCII}`、`\p{Assigned}`、`\p{Emoji}`
  - POSIX の文字クラスと同じ範囲の `\p{Alnum}`、`\p{Word}`、`\p{Blank}`、`\p{Graph}`、`\p{Print}`、`\p{XDigit}`
  - 用字の略称（`\p{Hira}`）
  - `In_` を付けたブロックの名前（`\p{In_Hiragana}`、`\p{InGreekandCoptic}`）。`\p{Script=Hira}` の書き方と `\p{InGreek}` は使えません

## このツールでの扱い

- m フラグは常に付いているものとして扱い、フラグの選択欄に出しません
- i フラグは、検索ダイアログの「英大文字と小文字を区別する」のチェックを外したときに当たります。「コピー」のボタンは、i フラグを `(?i)` として正規表現の先頭に書きます。「テスト」の欄のコード例には、i フラグに合わせてチェックを入れるか外すかを書きます
- 文字クラスの入れ子と `&&` には、このツールは対応していません。C# の引き算の書き方 `[a-z-[aeiou]]` も、サクラエディタでは入れ子として読まれるので、書き方の誤りとして知らせます。`.` を置き換えると入れ子になる `[].]` も同じです
- 置き換えたために誤りになるときは、誤りの位置を置き換える前の正規表現の位置で示し、置き換えのためだと書き添えます
