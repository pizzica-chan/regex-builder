# POSIX の正規表現（GNU grep の BRE と ERE）

## 対象と資料

- 調べた処理系: Ubuntu 24.04（WSL）の GNU grep 3.11 と glibc 2.39。ロケールは `ja_JP.UTF-8`
  - POSIX ERE（拡張正規表現）は `grep -E`、POSIX BRE（基本正規表現）は `grep` で調べました
  - GNU grep では、POSIX の決まりにない `\w` や `\<` なども使えます（表では「GNU 独自」と書きます）。このツールは、それらも含めて GNU grep に合わせています
- 公式の資料
  - [POSIX: Regular Expressions（The Open Group Base Specifications の 9 章）](https://pubs.opengroup.org/onlinepubs/9799919799/basedefs/V1_chap09.html)
  - [GNU grep のマニュアル](https://www.gnu.org/software/grep/manual/grep.html)
- この資料の内容はどれも手元の grep で実際に動かした結果から書いています。公式の資料は、今回は読み直していません
- grep の結果は、ロケール（言語と文字コードの設定）と、grep が使う C のライブラリ（Linux では glibc）で変わります。違いは「ロケールと処理系による違い」に書きました

## BRE と ERE の書き方の違い

| 書き方 | ERE（`grep -E`） | BRE（`grep`） |
|---|---|---|
| グループ | `( )` | `\( \)` |
| 回数 | `{2,3}` | `\{2,3\}` |
| 1 回以上・なくてもよい | `+` `?` | `\+` `\?`（GNU 独自） |
| または | `\|` | `\\|`（GNU 独自） |
| `( ) { } + ? \|` | 特別な意味 | 文字のまま |
| `^` | どこでも行の先頭 | 正規表現の始め、`\(` のあと、`\|` のあとでだけ行の先頭。ほかは文字 |
| `$` | どこでも行の末尾 | 正規表現の終わり、`\)` の前、`\|` の前でだけ行の末尾。ほかは文字 |
| 正規表現の始めの `*` | 無視される（`*a` は `a`） | 文字のまま（`*a` は「*a」） |

## 一致の選び方

- **いちばん左で、いちばん長い一致を選びます。** `a|ab` を `xab` に使うと、`ab` に一致します。`(a|ab)(c|bcd)` を `abcd` に使うと、`abcd` 全体に一致します。JavaScript などのほかの 7 つの言語は、左から順に試して最初に成り立った候補を選ぶので、`a|ab` は `a` に一致します
- **grep は 1 行ずつ調べます。** `^` と `$` は、いつも行の先頭と末尾に一致し、改行をまたいで一致しません
- `grep -o` は、長さ 0 の一致を出しません。`a*` を `baa b` に使うと、一致は `aa` だけです
- 大文字と小文字を区別しないとき（`grep -i`）は、後方参照も区別しないで比べます

## 文字の集まり

すべてのコードポイントの文字を grep で調べ、次の範囲になりました。文字の分類は glibc のもので、ロケールが `ja_JP.UTF-8`、`en_US.UTF-8`、`C.UTF-8` のどれでも同じでした。

| 書き方 | 一致する文字（Unicode の性質で書いたもの） |
|---|---|
| `[:alpha:]` | Alphabetic と、0〜9 以外の数字（`\p{Nd}`）。ひらがな・漢字も、全角数字も含む |
| `[:digit:]` | 0〜9 だけ（全角数字は含まない） |
| `[:alnum:]` | Alphabetic と `\p{Nd}` |
| `[:upper:]` | Uppercase と `\p{Lt}`（Ⅰ や Ⓐ、ǅ も含む） |
| `[:lower:]` | Lowercase と、ǅ ǈ ǋ ǲ（ª や ⓐ も含む） |
| `[:space:]` と `\s` | White_Space から、U+0085 と、改行させない空白（U+00A0、U+2007、U+202F）を除いたもの（全角スペースは含む） |
| `[:blank:]` | タブと `\p{Zs}` から、改行させない空白を除いたもの |
| `[:punct:]` | `[:graph:]` のうち `[:alnum:]` でないもの（記号のほか、ソフトハイフンのような書式の文字、私用の文字、結合文字、改行させない空白も含む） |
| `[:cntrl:]` | `\p{Cc}` と U+2028、U+2029 |
| `[:print:]` | 制御文字（`\p{Cc}`）、サロゲート、未割り当て、U+2028、U+2029 以外 |
| `[:graph:]` | `[:print:]` から、改行させない空白以外の空白（`\p{Z}`）を除いたもの |
| `\w` | Alphabetic と `\p{Nd}` と `_`（`[[:alnum:]_]` と同じ） |

- glibc 2.39 は、ブラウザより古い Unicode を使っています。そのため、Unicode 16 で性質が変わった U+0363〜U+036F と U+1DD3〜U+1DE6 の結合文字 33 文字は `[:alpha:]` に入らず（`[:punct:]` に入る）、U+0295 は `[:lower:]` に入ります。glibc がまだ知らない新しい文字（87 の範囲の 9988 文字。U+088F など）は、どの集まりにも入りません。`.` と `[^a]` には一致します
- このツールは、これらの文字も glibc 2.39 にそろえています（`dialects.js` の `POSIX_UNKNOWN`）。新しい Unicode を使う glibc の grep では、これらの文字で結果が違うことがあります（推測で、確かめていません）
- `\d` はありません。`\d` は「d」という文字として読みます（実際の結果）。数字は `[[:digit:]]` と書きます
- `.` は、どんな文字にも一致します。CR（`\r`）にも一致します

## 文字クラス

- **文字クラスの中の `\` は文字のままです。** `[\n]` は `\` と `n` に一致し、改行には一致しません
- `]` は先頭に置くと文字になります（`[]a]`）。`-` は先頭か最後に置くと文字になります
- `[[=e=]]` は、ja_JP.UTF-8 では `e` だけに一致しました（`é` には一致しない）。`[[.-.]]` のように 1 文字の照合要素は書けますが、`[[.hyphen.]]` のような名前と、`[[.ch.]]` のような 2 文字以上は誤りです
- ASCII の範囲（`[a-z]`、`[A-z]` など）は、ja_JP.UTF-8 では文字の番号（コードポイント）の順です。ASCII の外の範囲は、ロケールの並び順（照合の順）で決まります。ja_JP.UTF-8 では、両端が「ぁ〜ん」か「ァ〜ヶ」の中にある範囲（`[ぁ-ん]`、`[ァ-ヶ]` など）は、コードポイントの順と同じでした（無作為に選んだものを含む 65 個の範囲で試しました）。一方、`[一-龠]` は 6274 字だけ、`[😀-🙏]` はどの文字にも一致しません。並び順の表にない文字を範囲の端にすると、誤り（Invalid collation character）になります。`[一-龯]`、`[가-힣]`、`[①-⑳]`、ゖ や ヷ を端にした範囲は誤りです。試した漢字の範囲（`[一-龠]`、`[一-龥]`、`[亜-熙]`、`[一-龯]`、`[一-鿿]`）は、どれも誤りになるか、一部の字にしか一致しませんでした。そのため、このツールの部品の欄には、POSIX のときは「漢字」を出しません
- 範囲のすぐあとに `-` で範囲を続けると誤りです（`[a-c-e]`）。`[:alpha:]` を範囲の端にすると誤りです
- `[:alpha:]` を文字クラスの外に書くと誤りです。`[[:alpha:]]` と書きます。`[[:word:]]` のような、ない名前も誤りです

## 位置

- `\<` は単語の始まり、`\>` は単語の終わり、`\b` は単語の区切り、`\B` は単語の区切りではない位置です。単語の文字は `\w` と同じです
- `` \` `` と `\'` は、文字列（grep では行）の先頭と末尾です
- 位置の部品のあとの `*` `+` `?` `{` は、ERE では無視され、BRE では `*` が文字になります。`^*a` は、ERE では `^a`、BRE では「行の先頭の *a」です

## 繰り返し

- `{n}`、`{n,}`、`{,m}`、`{n,m}`、`{,}` が書けます。回数は 32767 までです
- ERE では、`{` のあとが回数として読めないとき（`a{x}`、`a{1`、`a{ 1}`）は、文字のまま読みます。ただし、`{` のあとが数字と `,` だけで `}` で閉じるのに回数として正しくないとき（`a{}`、`a{1,2,3}`）は誤りです
- BRE では、閉じない `\{` は誤りです
- 繰り返しは重ねられます（`a**`、`a{2}{3}`）
- `^` を含む部分を `+`、`{2}`、`{0,2}`、`{2,}` などで繰り返すと、一致するはずの行を選ばないことがあります。`(A|(^\w+)){2}` は `AAx` の行を選びません（`AA` に一致するはず）。`(A?|(^\w*)?){2}` も `Ax` の行を選びません。`*`、`?`、`{1}` で繰り返したときと、同じ部分を `(A?|(^\w*)?)(A?|(^\w*)?)` と書き並べたときは選びます。ja_JP.UTF-8 と C.UTF-8 では起き、C ロケールでは起きませんでした（どれも実際の結果）。POSIX の決まりでは一致するはずなので、grep の不具合と考えられます（推測で、原因は調べていません）。このツールは、意味どおりに一致させ、この形の正規表現では「テスト」の欄に注意を出し、「ほかの言語で使うと」でも理由として出します
- ERE の正規表現の始め、`(` のあと、`|` のあとの `*` `+` `?` `{` は無視されます（`(?:a)` は「:a」に一致します）。ただし、`(?)` や `(*)` のように、無視される記号のすぐあとが `)` のときは誤りです

## グループと参照

- 参照は `\1`〜`\9` の 1 桁だけです。`\10` は `\1` と「0」です
- 参照できるのは、参照より前で閉じたグループだけです。`\1(a)` と、「または」の別の候補の中のグループへの参照（`(a)|\1b`）は誤りです。`(a|(b))\2` は書けます
- 名前付きグループ、`(?:…)`、先読み・後読み、最短一致（`*?`）はありません

## エスケープ

- `\` のあとの文字は、上に書いた特別なもの以外、その文字として読みます。`\t` は「t」、`\x41` は「x41」です
- 最後の `\` は誤りです

## 大文字と小文字を区別しないとき

grep は、一致する行を選ぶときと、選んだ行の中で一致の位置を求めるときで、少し違う決まりを使います。どちらも、大文字と小文字で形が変わる 3037 文字すべてを `grep -i` で調べた結果です。

- **一致する行を選ぶとき**: 正規表現の文字 c に対して、c の大文字 U と、U の小文字（その大文字が U に戻るとき）を同じとみなします。さらに、ſ、ı、ς のような「大文字にすると別の文字の大文字になる」小文字 18 文字の表（GNU grep が使う gnulib にある表と考えられます）のうち、大文字が U になるものも同じとみなします
- **一致の位置を求めるとき**: 1 文字の大文字にして同じになる文字を、同じとみなします
- どちらの決まりでも、ſ と s、ı と i、ς と σ は同じで、ケルビン記号（U+212A）と k、İ と i は別です。ß はほかのどの文字とも同じになりません
- glibc がまだ知らない文字は、ほかの文字と同じになりません。相手が知らない文字のときも同じです（ɤ は、Unicode 16 で大文字になった U+A7CB と同じにならない）
- 後方参照も、一致の位置を求めるときの決まりで比べます（`(k)\1` は kk と kK に一致し、k とケルビン記号には一致しない）
- 2 つの決まりが違うのは、ᲀ（U+1C80）のような U+1C80〜U+1C88 の 9 文字です。正規表現の В は、ᲀ だけの行には一致しませんが、ほかに一致がある行では ᲀ にも一致します。後方参照があるときも、行は同じように選びます（`(В)\1` は ᲀᲀ だけの行には一致しない）。このツールも、この 2 段で一致を探します
- grep の後方参照は、ȿ（UTF-8 で 2 バイト）のように、大文字（Ȿ、3 バイト）にするとバイト数が増える 18 文字で、行によって結果が変わります。`(ȿ)\1` は「ȿȿ」だけの行には一致しませんが、「aȿȿ」の中の ȿȿ には一致します。また、`(.).\1` は「ⱾⱾȿ」に一致しませんが、この行には決して一致しない `|q` を足した `(.).\1|q` は一致します。結果が正規表現の意味ではなく glibc の中の大きさで変わるので、glibc の欠陥です。大文字にした文字列を作るバッファの大きさの計算で、増えるバイト数を見込んでいないためと考えられます（推測で、glibc のソースは一部しか読んでいません）。このツールは、意味どおりに、どの行でも一致させます。大文字と小文字を区別しない後方参照があるときは、「テスト」の欄に注意を出し、「ほかの言語で使うと」でも理由として出します
- 範囲は、両端を大文字にしてから作ります。`[A-z]` は `[A-Z]` と同じになって `_` に一致せず、`[Z-z]` は Z と z だけに一致し、`[Z-a]` は順番が逆になるので誤りです
- `[[:upper:]]` と `[[:lower:]]` は、`[[:alpha:]]` と同じになります。`(?i)` のような書き方はないので、`grep -i` を付けたときのことです（「あ」にも一致します）

## ロケールと処理系による違い

照らし合わせの基準は、Linux（glibc）の GNU grep で、ロケールを ja_JP.UTF-8 にしたものです。ほかのロケールや処理系では、次の点が違いました。

- **en_US.UTF-8**: 範囲がロケールの並び順で決まるので、ASCII の範囲でも結果が変わります。`[a-z]` は é のような文字にも一致し、`[ぁ-ん]` はカタカナにも一致します。`[[=e=]]` は é にも一致します
- **C.UTF-8**（glibc）: ASCII の外の文字を使った範囲（`[ぁ-ん]`）は誤りになります
- **Git for Windows の grep 3.0**（C.UTF-8）: 文字の分類が glibc と違います（`[:alpha:]` に全角数字が入らない、`[:blank:]` と `[:space:]` に改行させない空白の U+00A0 が入る、など）。絵文字のような U+10000 以上の文字を繰り返す正規表現（`😀+`）に一致しません。`-U` を付けないと、行の終わりの CR を読む前に落とします

このツールは、範囲をいつもコードポイントの順で調べます。ASCII、ひらがな（ぁ〜ん）、カタカナ（ァ〜ヶ）のどれにも収まらない範囲を使ったときと、`[=e=]` を使ったときは、「テスト」の欄に注意を出します。

## このツールでの扱い

- 一致は、いちばん左で、いちばん長いものを探します（`match-core.js` の状態機械）。グループの位置は、見つけた範囲に終わりをそろえて JavaScript の正規表現で求めるので、POSIX の決まりと違うことがあります。グループがあるときは、「テスト」の欄に注意を出します
- 後方参照があるときは、状態機械にグループの始まりと終わりと後方参照の状態を足し、始まりの位置ごとにすべての道筋を試して、いちばん長い一致を探します。一致しなかったグループを参照すると、grep と同じく失敗します
- 状態機械の状態が 20000 を超えるほど正規表現が大きいときは、JavaScript と同じく左から順に試して最初に成り立った一致を出し、注意を出します。後方参照があって、試す道筋が 1 つの始まりの位置で 20 万を超えるときも、JavaScript の正規表現で探します（このときは注意を出せません）
- 「コピー」のボタンは、`grep -E '…'` のような bash などのシェルで打つ形にします
- 「テスト」の欄のコマンドの例は、テスト文字列を `printf` で 1 行ずつ `grep -o` に渡します。grep には g フラグに当たる指定がないので、g フラグがないときは `| head -n 1` を付けて、「テスト」の欄と同じく最初の一致だけを出します
- sed は grep と同じ書き方ですが、`\n` や `\t` などのエスケープが使える点が違うと考えられます（推測で、確かめていません）
