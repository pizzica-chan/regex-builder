# Java の正規表現（java.util.regex）

## 対象と公式の資料

- 調べた処理系: Java 21 の `java.util.regex.Pattern`
- 公式の資料: [Pattern（Java SE 21 の API ドキュメント）](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/regex/Pattern.html)
- Eclipse の検索・置換の正規表現も、このライブラリを使っています。そのため、このツールの Java のモードと同じ動きになります。ただし Eclipse には改行を表す `\R` や、置換の大文字・小文字をそろえる `\C` などの独自の書き方が足されています（一般的な知識による推測で、Eclipse の公式の資料では確かめていません）

## フラグ

| フラグ | 正規表現の中での書き方 | 意味 |
|---|---|---|
| `CASE_INSENSITIVE` | `(?i)` | 大文字と小文字を区別しない。**標準では英字（US-ASCII）だけ** |
| `UNICODE_CASE` | `(?u)` | `CASE_INSENSITIVE` を Unicode の文字にも効かせる |
| `MULTILINE` | `(?m)` | `^` と `$` を各行の先頭と末尾にも一致させる |
| `DOTALL` | `(?s)` | `.` を改行にも一致させる |
| `COMMENTS` | `(?x)` | 空白を無視し、`#` からをコメントにする |
| `UNIX_LINES` | `(?d)` | 改行を LF だけにする |
| `UNICODE_CHARACTER_CLASS` | `(?U)` | `\d` `\w` `\s` などを Unicode の文字にも広げる |

`(?i)` は、書いた位置から後ろ（グループの中ならグループの終わりまで）に効きます。あとに続く `|` の候補にも効くので、`a(?i)b|c` は `C` にも一致します（実際の結果）。`(?i:…)` は囲んだ範囲だけに効きます。g に当たるフラグはなく、`Matcher.find()` を繰り返して探します。

## 文字の集まり

- `\d` は `[0-9]`、`\w` は `[a-zA-Z_0-9]`、`\s` は `[ \t\n\x0B\f\r]` です。全角数字、ひらがな、全角スペースには一致しません
- `\h` は横方向の空白、`\v` は縦方向の空白（LF、VT、FF、CR、U+0085、U+2028、U+2029）です。ほかの言語の `\v` は垂直タブ 1 文字なので、意味が違います
- `\R` は改行の並び（CRLF か、改行の 1 文字）です
- `.` は改行（LF、CRLF、CR、U+0085、U+2028、U+2029）以外の 1 文字です。CR にも一致しません
- `UNICODE_CHARACTER_CLASS` を付けると、`\d` は `\p{IsDigit}`、`\s` は `\p{IsWhite_Space}` になります

## 位置

- `^` は入力の先頭です。MULTILINE のときは、改行の直後にも一致します。ただし入力の最後の改行の直後（入力の終わり）には一致しません
- `$` は入力の末尾と、**最後の改行の直前**に一致します。改行には CRLF、CR、U+0085 なども含まれます。MULTILINE のときは、各改行の直前にも一致します
- `\A` は入力の先頭、`\z` は入力の末尾、`\Z` は「最後の改行を除いた」入力の末尾です
- `\b` は `(?:(?<=\w)(?=\W)|(?<=\W)(?=\w))` と同じ意味です

## グループと参照

- 名前付きグループは `(?<name>…)`、参照は `\k<name>` です。名前には英字と数字だけが使え、1 文字目は英字にします。`_` と漢字は使えません（実際の結果）
- グループの番号は開き括弧の順に左から付きます。名前付きグループにも番号が付きます
- `\1`〜`\9` は常に後方参照です。2 桁以上の数字は、その数のグループがあれば後方参照、なければ数字を 1 つずつ減らして読み直します
- 一致しなかったグループを参照すると、その参照は失敗します（実際の結果）
- 量指定子で繰り返したグループが 2 回目に失敗したとき、前の回の値が残ります
- 先読み・後読み・アトミックグループ `(?>…)` と、強欲な繰り返し（`X*+` など）が使えます
- 後読みの中身に、上限のない繰り返し（`a+` など）も書けます。ただし、`(?<=a+b+)c` が `aabbc` に一致しないなど、正しく一致しないことがあります。`(?<=(?:ab)*)c` は誤りになりました（どれも実際の結果。公式の資料には書かれていません）。`a{1,3}` のように上限が決まっていれば、正しく一致します
- `(?#…)` のコメントと、`\g{n}` の書き方はありません

## エスケープ

- 8進数は `\0n`、`\0nn`、`\0mnn` のように必ず `\0` で始めます。`\0` だけでは誤りです
- `\xhh`、`\uhhhh`、`\x{h…h}`、`\N{名前}`、`\t \n \r \f \a \e`、`\cx` が使えます
- `\cx` は、x の文字の値の 0x40 のビットを反転した文字です。ほかの言語と違って小文字を大文字にしないので、`\cj` は LF ではなく `*` になります（実際の結果）
- 意味のない英字のエスケープ（`\q` など）は誤りです
- `\Q…\E` で囲んだ部分はすべて文字として読みます

## 文字クラス

- `[a-d[m-p]]` は和、`[a-z&&[^bc]]` は共通部分（差）です。ほかの言語では、`[` と `&` は文字として読まれます
- `\p{Lu}`、`\p{IsHiragana}`、`\p{script=Hiragana}`、`\p{InGreek}`（ブロック）、`\p{IsAlphabetic}`（二値の性質）などが使えます。`\pL` のように `{}` を省くこともできます。`\p{Lower}` などの POSIX の名前は標準では ASCII だけです
- POSIX の書き方 `[[:alpha:]]` はありません。Java では入れ子の文字クラスとして読まれます

## このツールでの扱い

- 大文字と小文字を区別しない指定は、英字（A〜Z、a〜z）だけに効かせます
- 「テスト」の欄では `$` と `\Z` を「末尾か、最後の改行（CRLF、LF、CR、U+0085、U+2028、U+2029）の直前」に置き換えて動かします。最後の改行が CRLF のとき、CR と LF の間には一致しません（実際の結果）
- 後読みの中の上限のない繰り返しは、正しく一致しないことがあるので、書き方の誤りとして知らせます
- 文字クラスの入れ子と `&&` には、このツールは対応していません
