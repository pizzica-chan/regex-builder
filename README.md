# 正規表現ビルダー

部品のボタンを押して正規表現を組み立てると、その正規表現の意味を日本語で表示する静的 Web サイトです。JavaScript・Python・Java・PHP・C#・PowerShell・Go・サクラエディタと、POSIX の ERE（`grep -E`）と BRE（`grep`）の 10 の書き方（方言）を切り替えられます。

## 使い方

ファイル一式を Web サーバーに置き、`index.html` を開きます。ビルドは要りません。

一致の計算は Web Worker（画面とは別に動く処理）で行い、1.5 秒を超えたら打ち切ります。そのため、計算が終わらない正規表現を試しても画面は固まりません。`index.html` をファイルのまま開くと、ブラウザによっては Web Worker が動きません。その場合は画面と同じ処理で計算するので、打ち切りは働きません。

- 「言語」の切り替え：「正規表現」の欄の見出しの横で、対象の言語を選びます。選んだ言語に合わせて、受け付ける書き方、「意味」の説明、部品のボタン、選べるフラグ、例の一覧、「コピー」の形が変わります。選んだ言語はブラウザに保存され、共有 URL にも入ります
- 「正規表現」の欄：ページを下へ動かしても画面の上に残ります。入力した正規表現は、部品の種類ごとに色を分けて表示し、書き方に誤りがあれば、その場所に波線を引きます。見出しの横に一致の件数を表示します。フラグにマウスを乗せると、説明と、そのフラグを付けないときと付けたときの一致の違いが出ます。
- 「部品」の欄：ボタンを押すと、正規表現の入力欄のカーソルの位置に入ります。`(…)` のように「…」の入ったボタンは文字を選んでから押すと、選んだ部分を囲みます。ボタンにマウスを乗せると、説明と例が出ます。「たたむ」ボタンで欄を閉じられます。
- 「意味」の欄：入力中の正規表現を、部品を順に並べた要約と、入れ子の詳しい説明で表示します。要約や説明の項目にマウスを乗せると、入力欄の対応する部分に色が付きます。反対に、入力欄の中にカーソルを置くと、その位置の部品の説明に色が付きます。
- 「ほかの言語で使うと」：「意味」の欄のいちばん下に、今の正規表現をほかの言語でそのまま使ったときに「同じ意味」「ほぼ同じ意味」「意味が変わる」「書けない」のどれになるかと、その理由を出します。その言語では書けても、このツールが対応していない書き方（Java の文字クラスの入れ子など）があるときは「調べられない」と出します
- 「テスト」の欄：入れた文字列のうち、一致した部分に色を付け、グループに一致した部分にはグループごとの色の下線を引きます。一致の表の行にマウスを乗せると、その一致に枠が付きます。行を押すと、テスト文字列の中でその一致を選んだ状態になります。
- 「行ごとに判定する」：テスト文字列の各行を別々の文字列として調べます。行ごとに「一致するはず」「一致しないはず」を選ぶと、期待どおりかを表示します。チェックボックスにマウスを乗せると、説明と例が出ます。
- 「コード例」：「テスト」の欄のいちばん下に、選んだ言語で今の正規表現とテスト文字列を使って一致を探すプログラムを出します。g フラグがあれば一致した部分を 1 行に 1 つずつ、なければ最初の一致を出します。POSIX の ERE と BRE では grep のコマンドを、サクラエディタでは検索の手順を出します。テスト文字列が空のときと 1000 文字を超えるときは、例の文字列を入れます。
- 「配置」：ページ右上のメニューで、「部品」「意味」「テスト」の欄の並べ方を6種類の型から選べます。選んだ型はブラウザに保存されます。幅が狭い画面では、「テスト」「意味」「部品」の順に縦一列に並びます。
- 「消去」のボタンと「例を読み込む」：書き換えたあとに出る「元に戻す」のボタンか Ctrl+Z で、前の状態に戻せます。
- 「コピー」のボタン：JavaScript では `/…/flags` の形で、ほかの言語ではその言語のコードの形（Python なら `re.compile(r'…')`、PowerShell なら `$text -match '…'`）でコピーします。
- 「共有 URL」のボタン：言語、正規表現、フラグ、テスト文字列（2000文字まで）、行ごとの期待を URL に入れてコピーします。

## JavaScript 以外の言語の試し方

ブラウザで動かせるのは JavaScript の正規表現だけです。そのため、JavaScript 以外の言語では正規表現を同じ意味の JavaScript の正規表現に置き換えてから「テスト」の欄で動かします（`translate.js`）。たとえば Python の `\d` は全角数字にも一致するので `\p{Nd}` に、Python の `$` は最後の改行の直前にも一致するので「末尾か、最後の改行の直前」を表す先読みに置き換えます。アトミックグループ `(?>…)` と強欲な繰り返し `*+` も、同じ動きをする書き方で再現します。

置き換えが正しいかは、各言語の処理系（Python 3.13、Java 21、PHP 8.3、.NET 7、PowerShell 7.7、Go 1.27、サクラエディタ 2.4 の bregonig.dll、Ubuntu 24.04 の GNU grep 3.11）で同じ正規表現を実際に動かし、一致した位置がすべて同じになることで確かめています（`tools/dialect-probe/`）。次の違いは JavaScript の正規表現では再現できないので、「テスト」の欄に注意を出します。

- 一致しなかったグループを参照したとき、JavaScript では空文字列として一致しますが、ほかの言語では失敗します
- C# と PowerShell は絵文字のような文字を 2 文字として数えますが、「テスト」の欄では 1 文字として数えます
- 大文字と小文字を区別しない後方参照は、言語によって同じとみなす文字（ſ と s など）が違いますが、「テスト」の欄では JavaScript の i フラグで比べます
- `(\w*?)*` のように、空の文字列にも一致する部分を 2 回以上繰り返すと、一致が変わることがあります。JavaScript は空で終わった回を数えずに中身のほかの候補を試し直しますが、ほかの言語はそこで繰り返しを終えるためです。0 回か 1 回の繰り返し（`?`）は、同じ動きになるように置き換えています

POSIX の ERE と BRE（GNU grep）は、いちばん左で、いちばん長い一致を選びます（`a|ab` は `ab` に一致）。JavaScript の正規表現ではこの選び方ができないので、正規表現を状態機械（NFA）に組み立て、grep と同じく 1 行ずつ、いちばん長い一致を探します（`translate.js` の `buildProgram` と `match-core.js` の `findAllPosix`）。後方参照があるときも、すべての道筋を試して、いちばん長い一致を探します。照らし合わせには、Ubuntu 24.04 の GNU grep をロケール ja_JP.UTF-8 で動かした結果を使い、文字の分類も、その glibc 2.39 にそろえています。次の 3 つは、「テスト」の欄に注意を出します。

- グループの位置は JavaScript の決まりで求めるので、POSIX の決まりと違うことがあります（一致の範囲は同じ）
- 正規表現がとても大きいとき（状態機械の状態が 20000 を超えるとき）は、JavaScript と同じく、左から順に試して最初に成り立った一致を出します
- 文字クラスの範囲は、文字の番号（コードポイント）の順で調べます。grep では、ASCII、ひらがな（ぁ〜ん）、カタカナ（ァ〜ヶ）のどれにも収まらない範囲は、ロケールの並び順で決まります。そのため、`[一-龠]` のような範囲では一致する文字が違い、`[一-龯]` のような範囲は誤りになります

各言語の正規表現の仕様は公式の資料と実際の動作を元に [docs/dialects/](docs/dialects/README.md) にまとめています。

## ファイル

| ファイル | 中身 |
|---|---|
| `index.html` | 画面 |
| `style.css` | 見た目（OS の設定に合わせてダークモードにも切り替わる） |
| `dialects.js` | 言語ごとの違い（使える書き方、`\d` などの範囲、`$` の扱い、コピーの形） |
| `regex-explain.js` | 正規表現を言語ごとの書き方で解析し、日本語の説明を作る |
| `translate.js` | JavaScript 以外の言語の正規表現を、同じ意味の JavaScript の正規表現に置き換える。「ほかの言語で使うと」の比較も作る |
| `app.js` | 部品、入力欄の色分け、説明の表示、一致の確認、行ごとの判定、共有 URL |
| `layout.js` | 欄の配置の型と切り替え |
| `match-core.js` | テスト文字列との一致を調べる処理。`match-worker.js` と `app.js` の両方から使う |
| `match-worker.js` | `match-core.js` の処理を、画面とは別の処理（Web Worker）で動かす |
| `docs/dialects/` | 10 の方言の正規表現の仕様の資料 |
| `tools/dialect-probe/` | 各言語の処理系で正規表現を実際に動かして調べる道具と、その結果。`run-all.ps1` で全部の言語を動かし、`verify.js` で「テスト」の欄の置き換えと照らし合わせる |
| `tools/test/` | JavaScript のモードの説明が変わっていないかを確かめる `js-regression.js`、「コード例」を各言語の処理系で動かし、「テスト」の欄と同じ一致を出すかを確かめる `sample-programs.js`、説明や比較を目で確かめる道具 |
| `favicon.svg`、`favicon.ico`、`apple-touch-icon.png` | ブラウザのタブやホーム画面に出るアイコン。`.ico` と `.png` は `python tools/make_favicons.py` で `favicon.svg` と同じ図形から作る（Pillow が要る） |

## 対応していないこと

- v フラグの集合演算（`[\w--\d]` など）の説明
- 正規表現の中に空白やコメントを書く x フラグ（`(?x)`）
- Java とサクラエディタの、文字クラスの入れ子（`[a[b]]`）と `&&`
- `\G`（前の一致が終わった位置）
- Python・PHP・C#・PowerShell・サクラエディタの条件分岐（`(?(1)…|…)`）と、PHP・サクラエディタの部分式の呼び出し（`\g<name>`、`(?1)`、`(?R)`）
- PHP の `(?|…)`（「または」の候補ごとにグループの番号をそろえる書き方）と、Java の `\b{g}`
- Python の `(?a)` と `(?u)`、Java の `(?u)` と `(?U)`、PHP と Go の `(?U)`、PHP・C#・PowerShell の `(?n)` のフラグ
- Python と Java の、文字の名前で書く `\N{…}`
- Java・PHP・サクラエディタの `\X`（見た目の 1 文字にまとまる文字の並び）と、PHP・サクラエディタの `\K`
